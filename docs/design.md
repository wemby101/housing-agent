# 청년 집 구하기 에이전트 — 설계 문서

작성일: 2026-11-16 · 대회: 2026 대한민국 청년 CAREER FAIR AI 해커톤 (제출 마감 2026-11-23 17:00, 본선 발표 12-07)
개발: 1인, 7일

## 1. 무엇을, 왜

처음 혼자 집을 구하는 청년은 두 가지를 동시에 모른다.
1. **이 집이 안전한가** — 전세사기 피해자의 다수가 20~30대.
2. **내가 받을 수 있는 지원이 뭔가** — 보증료 지원, 전세대출 등을 몰라서 못 받는다.

그리고 이 둘이 연결돼 있다는 것도 모른다. 예: 위험한 집이면 전세보증보험이 필수 → 청년은 보증료를 최대 40만 원 돌려받는다.

기존 서비스는 따로 논다. HUG 안심전세앱(2026-09 개편)은 전세 위험만 AI로 진단하고, 온통청년·복지로·토스는 지원금만 찾는다. **이 서비스의 차별점은 "집 위험 진단 + 내 지원 자격"을 한 번에 엮어 행동 계획으로 주는 것.**

## 2. 목표 / 비목표 / 반목표

**목표**
- 사용자가 나이·소득·집 주소·호수·보증금·월세(없으면 0)를 넣으면, 공공데이터로 계산한 위험 신호와 받을 수 있는 지원, 해야 할 일 목록을 돌려준다.
- **전세, 반전세, 월세를 모두 다룬다** (사용자 결정, 11/16). 청년은 월세가 많기 때문이다. 위험 판정은 계약 형태와 상관없이 **보증금**으로 계산한다. 보증금이 작으면 위험 신호도 자연히 작게 나온다. 지원 정책은 계약 형태에 맞춰 고른다. 예: 전세는 보증료 지원, 월세는 청년 월세 지원.
- 모든 숫자는 공공데이터에서 코드로 계산하고, 출처를 화면에 표시한다.
- 심사위원이 링크 하나로 직접 써볼 수 있는 웹 데모.

**비목표 (v1에서 안 함)**
- 서울 외 지역, 아파트·단독·다가구, **오피스텔** (아래 제약 참고).
- 등기부등본 자동 분석 (유료이고 잘못 읽으면 위험). 선순위 채권은 사용자가 직접 입력.
- 회원가입, 저장, 알림.
- 일반 길찾기·매물 검색.

**반목표 (기술적으로 돌아가도 실패로 보는 것)**
- **"안전합니다"라고 단정하는 것.** 결과는 "위험 신호 있음/없음"과 근거까지만. 최종 판단은 공인중개사·HUG 상담으로 안내.
- AI가 숫자를 만들어내는 것. AI는 계산하지 않는다.
- 근거 없는 지원 자격 판정 ("받을 수 있어요"는 조건을 코드로 확인한 경우만).

## 3. 제약

- **공공데이터 키**: data.go.kr(건축물대장·실거래가), 도로명주소(개발용 90일), 온통청년(심사 중). 키는 `.env`에만 두고 git에 올리지 않는다.
- **AI API 키 없이 시작**한다 (사용자 결정). 1~4일차는 AI 없이 동작해야 한다.
- **단, AI 대화 모드는 필수다.** 대회 공모주제가 "AI 에이전트 기반의 해결 서비스"라서, 폼 모드만으로는 주제에 맞지 않는다. AI 키(회사 선택 포함)는 **5일차(11/20) 전까지** 정한다.
- 로컬 Python은 3.9.6(macOS 기본). 최신 Streamlit이 더 높은 버전을 요구하면 별도 Python(3.11+)을 설치해 가상환경으로 쓴다.
- **오피스텔을 v1에서 뺀 이유**: HUG 126% 규칙의 기준인 "공시가격"은 공동주택(연립·다세대)에만 있고, 오피스텔은 국세청 기준시가 등 다른 기준을 쓴다. 근거가 불확실한 계산을 넣지 않기 위해 빌라(연립·다세대)만 다룬다. 시간이 남으면 추가 검토.

## 5. 구조

두 층으로 나눈다. **이게 핵심 설계 원칙: 계산은 코드, 설명은 AI.**

```
[화면: Streamlit]
   ├─ 입력 폼 모드 (AI 없이 동작, 1~4일차, 시연 백업용)
   └─ 대화 모드 (AI 에이전트, 키 생기면 추가)
          │  둘 다 같은 도구를 부른다
          ▼
[도구 층: 순수 Python 함수 — 테스트 대상]
   resolve_address(주소)        → 시군구코드, 법정동코드, 번, 지, 산여부
   get_building(코드, 번지)      → 주용도, 위반건축물 여부(가능하면), 세대수
   get_official_price(..., 호수) → 공시가격(주택가격)
   get_market_price(...)         → 같은 지번·비슷한 면적의 최근 매매 실거래가 → 추정 시세
   assess_risk(보증금, 선순위채권, 공시가격, 추정시세, 주용도) → 신호 목록 + 근거
   match_policies(나이, 소득, 지역, 보증금, 무주택여부)       → 받을 수 있는 지원 + 금액 + 서류
          │
          ▼
[데이터 출처] 도로명주소 API · 건축물대장 API · 연립다세대 매매/전월세 실거래가 API · 온통청년 API · 직접 정리한 핵심 정책표
```

### 5.1 위험 판정 규칙 (모두 코드)

| 신호 | 규칙 | 근거 |
|---|---|---|
| 보증보험 가입 불가 | (보증금 + 선순위 채권) > 공시가격 × 1.26 | HUG 전세보증 기준 (공시가격 126%) |
| 깡통전세 위험 | 보증금 비율 = 보증금 ÷ 추정 매매시세 (전세면 곧 전세가율). **80% 이상 위험, 70~80% 주의** | 업계에서 널리 쓰는 기준 — *내 판단, 화면에 "일반적 기준"으로 표시* |
| 주택이 아님 | 주용도가 근린생활시설 등 주택이 아닌 용도 | 보증·대출이 막힐 수 있음 |
| 위반건축물 | 건축물대장에 위반 표시가 있으면 | API 항목 위치는 키 받은 뒤 확인. 없으면 "직접 확인" 안내로 대체 |
| 시세 데이터 부족 | 비교 거래가 2건 미만이면 전세가율을 계산하지 않고 "시세 확인 불가"로 표시 | 근거 없는 숫자를 내지 않기 위해 |

**추정 시세 범위** *(내 판단)*: 먼저 같은 지번의 최근 24개월 매매를 본다. 2건 미만이면 같은 법정동에서 전용면적 ±20%, 건축년도 ±5년인 거래로 넓힌다. 빌라는 같은 지번 거래가 드물기 때문이다. 화면에는 어느 기준으로 계산했는지와 몇 건인지 표시한다.

**공시가격 출처** *(11/16 수정)*: 건축물대장 API의 "주택가격" 조회를 실제로 호출해 봤더니, 관악구 다세대 4곳 모두 결과가 0건이었다. 빌라(공동주택) 공시가격은 **브이월드(VWorld) 공동주택가격 속성조회 API**(`https://api.vworld.kr/ned/data/getApartHousingPriceAttr`)에서 가져온다. 이 API는 PNU(19자리)와 동·호로 조회하고, 별도 브이월드 키가 필요하다. 조회에 실패하면 사용자가 직접 입력하게 하고, 출처를 "사용자 입력"으로 표시한다. 이때 부동산공시가격알리미(realtyprice.kr) 링크도 같이 안내한다.

**입력 추가**: 전용면적(㎡)을 입력받는다. 시세를 추정할 때 같은 면적끼리 비교하기 위해서다. 계약서나 매물 정보에 항상 적혀 있다.

**협상 목표 보증금** *(내 판단)*: 아래 두 값 중 낮은 값으로 정한다. 시세를 모르면 첫 번째 값만 쓴다. 화면에는 계산식을 같이 보여준다.
- 공시가격 × 1.26 − 선순위 채권 (보증보험 한도)
- 추정 시세 × 0.7 (주의 구간 아래)

선순위 채권을 모르면 0으로 계산하되, "등기부등본에서 근저당을 꼭 확인하세요" 경고를 크게 띄운다.

**전월세 실거래가 API는 v1에서 쓰지 않는다** *(내 판단)*. 전세가율은 매매 시세로 계산하기 때문이다.

### 5.2 지원 정책 매칭

- **소득 입력** *(내 판단)*: 본인 연소득(세전 총급여)과 혼인 여부를 받는다. 기혼이면 부부 합산 소득을 받는다. 국토부 보증료 지원 기준이 이 방식이다. 중위소득 % 기준인 정책은 "조건 확인 필요"로 분리한다.
- **정책표는 Claude가 공식 출처(gov.kr, 서울주거포털, HUG)에서 조사**하고, 정책마다 출처 링크와 확인한 날짜를 저장한다. 확인한 5개 정도로 시작한다. 사용자는 발표 전에 한 번 훑어본다.
- **핵심 정책표(직접 정리, 확실한 것)**: 국토부 전세보증금반환보증 보증료 지원(보증금 3억 이하, 청년 연소득 5천만 원 이하, 최대 40만 원, 무주택), 청년 월세 지원(국토부·서울시) 등 서울 청년 주거 지원 5~10개. 정책마다 해당하는 계약 형태(전세/월세/공통)를 붙인다. 조건·금액·서류·신청 링크를 출처와 함께 저장.
- **온통청년 API(보조)**: 키 승인되면 나이·지역·소득·주거 키워드로 추가 후보를 보여주되, 조건이 자동 판정 안 되는 건 "조건 확인 필요"로 분리.
- 온통청년 승인이 늦어도 핵심 정책표만으로 데모가 성립한다.

### 5.3 결과 화면

1. 한 줄 결론 (예: "⚠️ 보증보험 가입 한도를 1,840만 원 넘어요")
2. 신호별 카드: 무엇이 문제인지 / 숫자 / 출처
3. 받을 수 있는 지원과 예상 금액 합계
4. 해야 할 일 체크리스트 (협상 목표 보증금, 넣을 특약, 준비 서류)
5. 고지문: "참고용 진단입니다. 계약 전 공인중개사·HUG(1566-9009) 상담으로 확인하세요."

### 5.4 AI 에이전트 층 (키 생긴 뒤)

- 대화로 위 입력값을 모으고, 도구를 호출하고, 결과를 쉬운 말로 설명하고, 행동 계획을 쓴다.
- AI는 숫자를 직접 계산하지 않는다. 도구 결과의 숫자만 인용한다.
- AI 회사 연결부는 한 파일에 모아 교체 가능하게 한다 (Claude 또는 다른 회사).
